# Основи програмування — комп'ютер, який видно

[English](README.md) · [Українською](README.uk.md)

> «У комп'ютері є лише біти. Типи, імена й мови — це спосіб про них думати.»

**16 тижнів, вісім лабораторних**, розраховано на перший курс: вміння програмувати не потрібно. [Нульовий тиждень](setup.notes.md) ставить інструменти, [C++ за годину](cpp-survival-kit.notes.md) дає саме ту мову, якої вистачить на Lab 1, а сама Lab 1 починається не з порожнього файлу, а з [готового скелета](starter/README.md). За семестр ви збираєте **один** маленький віртуальний комп'ютер. На восьмій лабі вже пишете для нього програми текстом — як звичайну мову. Лексер і асемблер ваші: з цього тексту роблять байти, процесор їх виконує. Репозиторій можна клонувати, запустити однією командою — і побачити дамп пам'яті, пікселі в терміналі й Фібоначчі на стеку, який ви зробили самі.

У лабах ця програма називається **`ember`**. Це не готова бібліотека і не нова мова — це те, що ви пишете. Назва одна, щоб тексти лаб могли на неї посилатись; свій репозиторій можна назвати інакше. Машина в усіх одна: пам'ять, регістри, екран, асемблер. Відрізняються README, додаткові інструкції, якщо захочете, і програми, які ви для неї напишете.

## Як влаштований курс

У кожній лабі дві частини, і вони тримаються купи:

1. **Одна ідея** — як програми насправді працюють: коротко, з типовими помилками і кількома дослідами в терміналі.
2. **Один крок `ember`**, без якого ця ідея так і лишилась би слайдом. Байт перескакує з 255 на 0 — ось цілі типи. Інструкція закодована в байті — ось біти. Процесор шукає значення в пам'яті, а не тримає все в регістрах — ось вказівники. Екран це сітка — ось масиви. Набридло тикати шістнадцяткові байти руками — ось лексер і рядок `ADD A, B`.

Віртуальний комп'ютер зручний тим, що все можна побачити. Переповнення — у дампі. Вилізли за масив — санітайзер сам надрукує звіт. Рекурсія — стек росте, доки не впреться. Текст стає інструкціями, бо ви написали сканер.

Усе робиться в **терміналі**: збираєте через `c++` і `cmake`, `ember` приймає команди, вивід копіюєте в README. Це і є перевірка.

## Проєкт: `ember`

`ember` — звичайна програма на C++, яка грає роль маленького комп'ютера:

- 4096 байтів пам'яті, які можна надрукувати (`dump`)
- кілька регістрів — іменованих комірок, з якими процесор працює просто зараз
- набір інструкцій, який ви додаєте по одній
- з Lab 5 — екран 64×32 символами в терміналі
- з Lab 8 — асемблер: пишете `ADD A, B`, а не набираєте шістнадцяткові байти

Запуск як у будь-якої консольної програми: `./build/ember`. З'являється prompt — рядок, куди пишете команду. Пишете `dump`, `get 0`, `step`. Пізніше: `./build/ember programs/fib.asm`.

### Ті самі 4 КБ у всіх

Усі лаби показують на одну картинку. Записана вона один раз — у **[ISA.uk.md](ISA.uk.md)**:
карта пам'яті й набір інструкцій, зафіксовані в Lab 2 і доповнювані по кілька
рядків за лабу.

```txt
0x000  CODE  2048 Б   ваша програма; звідси стартує PC
0x800  DATA   512 Б   рядки, масиви, лічильники
0xA00  VRAM   256 Б   64 x 32 пікселі по біту — екран це і є пам'ять
0xB00  запас  256 Б
0xC00  HEAP   768 Б   ALLOC відрізає вгору
0xF00  STACK  256 Б   SP стартує з 0xFFF і йде вниз
```

Усі збирають ту саму машину. Відрізняються README, додаткові інструкції, якщо захочете, і програми, які ви для неї напишете.

## Слова, якими говорять лаби

Прочитайте один раз. Далі тексти вважають, що ці слова вже зрозумілі. Тут — те, що
стосується саме `ember`; повний двомовний словник курсу лежить у
[GLOSSARY.md](GLOSSARY.md).

| Слово | English | Що це тут значить |
|---|---|---|
| **`ember`** | — | Назва вашого проєкту — віртуального комп'ютера на C++. Можна перейменувати. |
| **Віртуальна машина (VM)** | virtual machine | Програма, яка поводиться як процесор плюс пам'ять. `ember` якраз така. |
| **Байт** | byte | 8 бітів. Одна комірка пам'яті `ember`. |
| **Дамп** | dump, hexdump | Надрукувати пам'ять шістнадцятковим записом (і ASCII), як утиліта `hexdump`. Команда: `dump`. |
| **Peek / poke** (`get` / `set`) | peek / poke | Прочитати байт за адресою; записати байт за адресою. |
| **CLI / prompt** | command line, prompt | Програма в терміналі, якій ви пишете команди. Без окремого вікна, без кнопки Run. |
| **Регістр** | register | Іменована комірка всередині процесора (`A`, `B`, `PC`), яка тримає значення зараз. |
| **`PC`, лічильник команд** | program counter | Адреса наступної інструкції. |
| **Опкод** | opcode | Байт (або шматок байта), який каже, *яка* це інструкція (`ADD`, `HALT`, …). |
| **ALU** | arithmetic logic unit | Блок арифметики й логіки: додає, робить AND, зсуває. У нас це функції на C++, які ви пишете. |
| **Гість і хост** (guest / host) | guest / host | *Гість* — числа всередині `ember` (адреса від 0 до 4095). *Хост* — ваш справжній процес C++ (вказівник `Byte*` на масив). Це різні світи, їх не змішують. |
| **Асемблер** | assembler | Програма, яка з тексту на кшталт `ADD A, B` робить байти, які команда `step` уже вміє виконати. |
| **Лексер / сканер** | lexer, scanner | Перший крок: іде по символах, видає токени або пише помилку з номером рядка. |
| **Санітайзер** | sanitizer | Додаткові перевірки, які компілятор вшиває в програму. Вилізли за масив — програма падає і друкує звіт, а не «ну, 42». |
| **ASan** | AddressSanitizer | **AddressSanitizer** (`-fsanitize=address`). Ловить вихід за межі масиву, читання після `delete`, подвійний `delete`. |
| **UBSan** | UndefinedBehaviorSanitizer | **UndefinedBehaviorSanitizer** (`-fsanitize=undefined`). Ловить, зокрема, переповнення знакового `int`. |
| **Невизначена поведінка, UB** | undefined behaviour | Мова не обіцяє, що буде. Санітайзери частину цього показують одразу. |
| **CMake** | — | Збірка проєкту: описуєте його один раз, далі `cmake --build` збирає однаково на macOS, Linux і Windows. |
| **`H`** | address register | Адресний регістр: 16 бітів, тримає *де*, а не *що*. Вказівник усередині процесора. |
| **`SP`** | stack pointer | Вказівник стека. `PUSH` кладе під нього, `POP` знімає назад. |
| **Відеопам'ять, VRAM** | framebuffer, VRAM | 256 байтів пам'яті `ember`, з яких зроблено екран. Не окремий масив — [ISA.uk.md §7](ISA.uk.md#7-екран-це-память). |

## З чого складається лаба

Той самий каркас, що в Python- і JavaScript-курсах:

1. **Терміни цієї лаби** — 5–8 слів, які вона вводить, українською й англійською.
2. **Про що ця лаба** — що саме ви з неї берете і навіщо воно потім.
3. **Notes** — коротка теорія, фрагменти коду, очікуваний вивід. На парі чи вдома. Лабу не замінює.
4. **Теорія** — як це влаштовано, типові помилки, досліди. Це читання.
5. **Крок проєкту** — що додати в `ember`, етапи і коли вважати готовим.
6. **Рівні** — Basic / Standard / Advanced з чесною оцінкою годин. Оберіть рівень **до** початку: Basic — це нормально здана лаба, а не провал.
7. **Чекліст здачі**.
8. **На захисті** — питання до дошки.
9. **Якщо встигаєте** — необов'язкове, коли йдете з випередженням.
10. **Що почитати й подивитись** — кілька відео й текстів, біля кожного рядок, навіщо саме це.

### Що де живе, щоб не читати одне двічі

У кожної речі один дім. Якщо вона потрібна в другому файлі — там стоїть посилання,
а не копія. Це не акуратність заради акуратності: студент першого курсу читає обидва
файли поспіль, і кожен повтор він сприймає як нову інформацію, поки не здогадається,
що це те саме.

| Річ | Дім |
|---|---|
| Терміни, теорія, етапи, рівні, чекліст, питання на захист | **лаба** |
| Фрагменти коду, рядок збірки, очікуваний вивід, «якщо мало часу» | **notes** |
| Карта пам'яті, інструкції, конвенція виклику | [ISA.uk.md](ISA.uk.md) |
| Числа, з якими звіряються | [CHECKS.md](CHECKS.md) |
| Як іде захист, варіанти трасування, завдання «зламав викладач» | [DEFENSE.md](DEFENSE.md) |
| Вправа на парі: програму виконують руками, без ноутбука | [PAPER-CPU.md](PAPER-CPU.md) |
| Де кожна ідея курсу живе в справжньому залізі й навіщо вона в оборонці та embedded | [HARDWARE.md](HARDWARE.md) |
| Терміни українською й англійською | [GLOSSARY.md](GLOSSARY.md) |

Лаба каже, **з чим ви маєте вийти** з кожного досліду; notes тримають сам дослід.
Тому «Перевірте самі» в лабі — це таблиця висновків, а не другий екземпляр коду.

### Про рівні, бо група нерівна

На перший курс приходять по-різному: хтось писав код у школі, хтось не відкривав
термінал. Курс розводить це **рівнями**, а не двома програмами.

- **Basic** — це повноцінно здана лаба. Розрахована так, щоб людина, яка не
  програмувала ніколи, дійшла за **4–5 годин на тиждень**, користуючись готовим
  кодом. Студент, який усі вісім лаб зробив на Basic, усе одно зібрав робочий
  віртуальний комп'ютер — і йому варто це сказати вголос.
- **Standard** — цільовий рівень, **6–7 годин на тиждень**. Саме тут курс
  виконує свої обіцянки: трасування, пояснення, README.
- **Advanced** існує, щоб сильним було куди рости. Це навмисно **та сама машина,
  тільки складніше**, а не «зроби ще одну лабу». Так уся група захищає один
  артефакт однією мовою.

Разом за вісім лаб це приблизно **62–78 годин** на Basic і **102–118** на
Standard. За фіксований семестр плануйте групу під Standard і закладайте реальний
хвіст на Basic.

Частину роботи **дано готовим кодом, який треба прочитати, а не написати**:
prompt і дамп у Lab 1, `cpu.hpp`, форма `step()` і команда `reg` у Lab 2, `get16` у Lab 3, `show()` у Lab 5, лістинг `fact` у Lab 7,
список токенів і каркас лексера в Lab 8. Щоразу дається риштування, а лишається сама ідея лаби.
Читати чужий робочий код — навичка, якої курс навчає свідомо.

Три рівні лягають на загальну рубрику з [`INSTRUCTOR_HANDBOOK.md`](../../INSTRUCTOR_HANDBOOK.md) §6: Basic — зараховано, Standard — цільовий, Advanced — відмінно.

## Правила курсу

- **Самі.** Наприкінці ви маєте тримати всю машину в голові — це і є сенс.
- **Машина одна.** Карта пам'яті й набір інструкцій у [ISA.uk.md](ISA.uk.md) однакові в усіх. Свої інструкції додавайте в зарезервований діапазон; те, що вже є, не перевизначайте.
- **Один репозиторій з першого дня.** Публічний GitHub, коміти по ходу, тег після кожної лаби (`lab-01`, `lab-02`, …).
- **README здаєте разом із кодом.** Після кожної лаби — розділ: що зробили, вивід з термінала, що здивувало. У Lab 8 це вже розповідь про весь проєкт.
- **Працюємо в терміналі.** Збірка, запуск, перевірка. Фрагменти з notes — `c++ … scratch.cpp`. `ember` — програма, якій пишете команди. Доказ — **скопійований вивід** (і повідомлення санітайзера).
- **Після кожної лаби — п'ять хвилин захисту.** Прогнати перевірки лаби, простежити на папері кілька байтів із числами, яких ви не бачили, передбачити, що зламає один змінений рядок, і відповісти на одне питання. Рядок, який не можете пояснити, не рахується. Формат — у [DEFENSE.md](DEFENSE.md).
- **ШІ-асистенти дозволені.** Як ними користуватись і не обійти при цьому розуміння — [окремий розділ нижче](#ші-асистенти).
- **Санітайзери не вимикаємо.** Якщо поведінка невизначена, програма не «працює», навіть коли щось надрукувала.

## ШІ-асистенти

Скажімо чесно: асистент напише `ember` за вечір. [ISA.uk.md](ISA.uk.md) і
[CHECKS.md](CHECKS.md) описують машину так точно, що одного запиту досить, щоб
пройти всі перевірки. Тому код і вставлений вивід показують, що машина працює, але
не показують, що ви її розумієте. Це показує захист: трасування на папері з числами,
яких ви не бачили, і рядок, який змінить викладач ([DEFENSE.md](DEFENSE.md)).
Асистента там поруч не буде.

Лаба ваша, якщо ви можете змінити будь-який її рядок і наперед сказати, що
станеться. Хто цей рядок надрукував, неважливо.

| Віддавайте асистентові | Робіть самі |
|---|---|
| обв'язку: розбір команд, форматування виводу, `CMakeLists.txt`, розкладку по файлах | рядки, заради яких існує лаба: маска в `decode`, прапорці, на скільки рухається `PC`, формула `plot`, порядок байтів у `CALL`/`RET`, мітки в асемблері |
| пояснення незрозумілої помилки компілятора чи звіту ASan | прогноз перед кожним запуском: що надрукує і чому |
| «поясни мені цей рядок» про код, який дано в лабі | трасування на папері |
| перевірку: «чи збігається мій `step` з таблицею в ISA?» | висновок, коли прогноз і машина розійшлись |

Одна звичка, яка окупається: отримали код від асистента — спершу передбачте, що
він видасть на `checks/`, і лише тоді запускайте. Асистенти помиляються
правдоподібно: `PC` зсувається не на стільки, перенесення береться не з того біта,
байти лягають не в тому порядку. Це саме ті баги, які ловлять трасування й перевірки. А
пройдені перевірки ще не означають правильний код: у
[DEFENSE.md](DEFENSE.md#lab-2--біти-не-брешуть) (поломка 4 у Lab 2) є зламаний
`step`, який їх майже проходить.

Загальні правила програми — у [README репозиторію](../../README.md#using-ai-assistants).

## Чим збираємо

- **C++17** або новіший. Беремо типи, функції, `struct`, вказівники. Без ієрархій класів. `std::vector` і `std::string` можна порівняти зі своїм кодом *після* того, як зробили річ руками.
- **CMake**

  ```bash
  cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
  cmake --build build
  ./build/ember
  ```

- **clang або gcc** у терміналі (`c++`, `clang++` чи `g++`):  
  `-std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined`  
  На Windows зручніше WSL (або інша Unix-оболонка), інакше ASan/UBSan часто не живуть.
- **Досліди з notes**

  ```bash
  c++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined scratch.cpp -o scratch && ./scratch
  ```

  Той самий рядок стоїть на початку [Notes 01](lab-01-a-box-of-bytes.notes.md).
- **clang-format** — оберіть стиль у Lab 1 і забудьте.
- **Налагоджувач (debugger) не обов'язковий.** Якщо вже берете — `lldb` або `gdb` у тому ж терміналі. Обов'язково — надрукувати байт через `get` або `std::cout`.
- **[Compiler Explorer](https://godbolt.org/)** — за бажанням, у «Якщо встигаєте». Обов'язкові завдання робимо в своєму терміналі.

- **[Crafting Interpreters](https://craftinginterpreters.com/)** — сканер і токени (Lab 8). Lox збирати не треба — нам важливий сам підхід.
- **[CS:APP](https://csapp.cs.cmu.edu/)** — біти, пам'ять, машинний код, коли захочеться копнути глибше в Lab 2–3.
- **[Crash Course Computer Science](https://www.youtube.com/playlist?list=PL8dPuuaLjXtNlUrzyH5r6jN9ulIgZBpdo)** — двійкова система, регістри, машинний код за десять хвилин.

## Що зможете сказати наприкінці

- *«Ось віртуальний комп'ютер на 4 КБ. Ось дамп, ось лічильник команд, ось піксель, який я поставив.»*
- *«Інструкції — це байти. Я виймаю поля масками і складаю ADD по бітах, а через звичайний `+` у C++ перевіряю себе.»*
- *«Виклик функції — не магія: `CALL` кладе адресу повернення, `RET` знімає. Можу показати, як Фібоначчі переповнює стек.»*
- *«Лексер з `ADD A, B` робить токени, асемблер з токенів — байти, які процесор уже розумів. Саме тому Фібоначчі вийшов у двадцять рядків, а не в сорок адрес переходів, порахованих руками.»*
- *«Екран — це 256 байтів тієї самої пам'яті, яку я дампаю. Ось байт, ось його вісім пікселів.»*
- *«Можу пояснити доповняльний код, чому `0.1 + 0.2` не дорівнює `0.3`, що таке вказівник, і що написав AddressSanitizer, коли я вийшов за масив.»*

Починайте з [нульового тижня](setup.notes.md), далі [Lab 1](lab-01-a-box-of-bytes.md).
