## Ідея

Комп'ютер не знає про «цілі числа». Він знає **байти**. Тип — це обіцянка, як їх читати. `int` зазвичай 4 байти, `char` — один, і той самий байт `01000001` це і 65, і літера `'A'`.

Ти пишеш текст. Компілятор перекладає. Синтаксична помилка — перекладу не було. Попередження — «законно, але підозріло»; у нас `-Werror`. Помилка виконання — програма вже біжить і робить щось недозволене: вихід за межі масиву, читання неініціалізованої пам'яті. Саме для цього санітайзери.

```mermaid
flowchart LR
  Src["source.cpp"] --> Cc["compiler"]
  Cc -->|"syntax error"| Stop["no program"]
  Cc -->|"ok"| Bin["ember"]
  Bin --> Run["run"]
  Run -->|"ASan / UBSan"| Report["report + abort"]
  Run -->|"ok"| Dump["dump / get / set"]
```

У `ember` це видно одразу: 4096 байтів, команда `get` друкує **чотири** способи показати ту саму комірку.

## 1. `sizeof` — ширина на *цій* машині

Не вчи таблицю з підручника. Надрукуй.

### Спробуй

```cpp
#include <iostream>
#include <cstdint>
int main() {
    std::cout << sizeof(char) << ' ' << sizeof(int) << ' '
              << sizeof(float) << ' ' << sizeof(double) << ' '
              << sizeof(void*) << '\n';
    std::cout << sizeof(std::uint8_t) << ' ' << sizeof(std::uint16_t) << '\n';
}
```

**Очікуй** (типова 64-бітна машина): `1 4 4 8 8` і `1 2`. Якщо інакше — пиши *своє* в README. `std::uint8_t` завжди 1; саме тому комірка VM — він, а не «просто `int`».

---

## 2. Переповнення: загортання проти UB

Беззнакове 8-бітне: після 255 йде 0. Це **визначено**. Переповнення знакового `int` — **UB**; з UBSan програма може впасти, без нього — «працювати» дивно.

### Спробуй

```cpp
#include <iostream>
#include <cstdint>
int main() {
    std::uint8_t u = 255;
    u = (std::uint8_t)(u + 1);
    std::cout << (int)u << '\n';          // 0

    int s = 2147483647;
    s = s + 1;                            // UBSan: signed overflow
    std::cout << s << '\n';
}
```

Збирай з `-fsanitize=undefined`. **Очікуй:** перший рядок `0`; другий — звіт UBSan.

**У ember:** комірки пам'яті — `uint8_t`. ALU наступної лаби теж загортає. Знаковий `int` — для лічильників у C++-програмі (хост), не для байтів усередині `ember` (гість).

## 3. Числа з рухомою комою

Більшість десяткових дробів не мають точного бітового запису.

### Спробуй

```cpp
#include <iostream>
int main() {
    std::cout << (0.1 + 0.2) << '\n';
    std::cout << std::boolalpha << (0.1 + 0.2 == 0.3) << '\n';
}
```

**Очікуй:** щось на кшталт `0.3` на екрані (округлення друку) і `false` в порівнянні.

**Навіщо:** пікселі, адреси, лічильники — цілі. `float` лише коли величина справді приблизна.

## 4. Символ — це теж число

ASCII `'A'` = 65 = `0x41`.

### Спробуй

```cpp
#include <iostream>
int main() {
    std::cout << 65 << ' ' << 0x41 << ' '
              << (int)'A' << ' '
              << (char)65 << '\n';
    std::cout << (char)('A' + 1) << '\n';
    std::cout << 5 / 2 << ' ' << 5 / 2.0 << '\n';
}
```

**Очікуй:** `65 65 65 A`, потім `B`, потім `2 2.5`. Цілочисельне ділення **відкидає** дріб.

`int x;` без ініціалізації — сміття. Завжди `int x = 0;` або `Byte data[4096]{}` — фігурні дужки **занулюють** пам'ять ember.
