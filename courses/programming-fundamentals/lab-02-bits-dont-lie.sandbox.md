## 1. Парне чи непарне

Процесор не ділить, щоб перевірити парність: йому досить подивитись на один молодший біт.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    int numbers[] = {7, 10, -3};
    for (int i = 0; i < 3; ++i) {
        int x = numbers[i];
        std::cout << x << ": " << (x % 2) << ' ' << (x & 1) << '\n';
    }
}
```

**Вгадайте:** що надрукують `x % 2` і `x & 1` для кожного з трьох чисел?

**Зміни одне:** котрий із двох виразів можна брати, щоб перевірити «непарне», якщо числа бувають від'ємні: `x % 2 == 1` чи `(x & 1) == 1`? Відповідь уже є у виводі.

**Що це означає:** молодший біт каже про парність і для від'ємних чисел, а `%` зберігає знак ([теорія §3](lab-02-bits-dont-lie.md#3-шість-операторів-і-два-з-них-кусаються)).

## 2. Степінь двійки одним рядком

У степеня двійки рівно одна одиниця в двійковому записі. Вираз `x & (x - 1)` знімає наймолодшу одиницю — отже, для степеня двійки дає нуль.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    int numbers[] = {1, 2, 6, 64, 96, 0};
    for (int i = 0; i < 6; ++i) {
        int x = numbers[i];
        bool power = (x & (x - 1)) == 0;
        std::cout << x << (power ? " так" : " ні") << '\n';
    }
}
```

**Вгадайте:** для кожного з шести чисел — «так» чи «ні»?

**Зміни одне:** рядок `bool power = …` замініть на `x != 0 && (x & (x - 1)) == 0`. Що змінилось?

**Що це означає:** `x - 1` перевертає всі біти від наймолодшої одиниці вниз, а `&` лишає лише те, що вище ([теорія §4](lab-02-bits-dont-lie.md#4-маски-як-інструкція-розкладається-на-поля)). Нуль — пастка: одиниць у ньому немає зовсім.

## 3. Геймпад в одному байті

Контролер приставки NES передавав стан усіх восьми кнопок одним байтом: кожна кнопка — свій біт.

```cpp
#include <cstdint>
#include <iostream>
const std::uint8_t UP = 1u << 0, DOWN = 1u << 1, LEFT = 1u << 2, RIGHT = 1u << 3;
const std::uint8_t BTN_A = 1u << 4, BTN_B = 1u << 5;
int main() {
    std::uint8_t pad = 0;
    pad |= UP;
    pad |= BTN_A;
    pad |= RIGHT;
    pad &= (std::uint8_t)~UP;
    std::cout << (int)pad << ":";
    std::uint8_t buttons[] = {UP, DOWN, LEFT, RIGHT, BTN_A, BTN_B};
    for (int i = 0; i < 6; ++i) {
        std::cout << ' ' << ((pad & buttons[i]) != 0);
    }
    std::cout << '\n';
}
```

**Вгадайте:** число після `pad` і шість нулів чи одиниць: натиснуті кнопки в порядку UP, DOWN, LEFT, RIGHT, A, B.

**Зміни одне:** після рядка з `&= ~UP` допишіть `pad ^= LEFT;` двічі, а потім `pad ^= DOWN;`. Що тепер?

**Що це означає:** `|=` виставляє біт, `&= ~` скидає, `^=` перемикає, `&` перевіряє ([теорія §4](lab-02-bits-dont-lie.md#4-маски-як-інструкція-розкладається-на-поля)).

## 4. −1 у різних костюмах

Ті самі біти читаються по-різному залежно від типу. Усі одиниці — це і найбільше беззнакове число, і −1.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    std::cout << (int)(std::uint8_t)-1 << '\n';
    std::cout << (int)(std::int8_t)0xFF << '\n';
    std::cout << ~0 << '\n';
    std::cout << (unsigned)-1 << '\n';
}
```

**Вгадайте:** чотири рядки.

**Зміни одне:** у першому рядку замініть `std::uint8_t` на `std::uint16_t`.

**Що це означає:** доповняльний код: −1 — це всі біти одиниці ([теорія §2](lab-02-bits-dont-lie.md#2-доповняльний-код-відємні-числа--це-просто-біти)).

## 5. Пастка пріоритету

Один із двох багів, на які в цій лабі наступає кожен.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    int flags = 6;
    if (flags & 4 == 4) {
        std::cout << "bit 2 is set\n";
    } else {
        std::cout << "bit 2 is clear\n";
    }
}
```

**Вгадайте:** що надрукує програма: `set` чи `clear`? Потім зберіть.

**Зміни одне:** спершу приберіть `-Werror` з рядка збірки й запустіть. Потім поверніть його й візьміть умову в дужки: `(flags & 4) == 4`.

**Що це означає:** `==` зв'язує тісніше за `&`, тож без дужок це `flags & (4 == 4)` ([теорія §3](lab-02-bits-dont-lie.md#3-шість-операторів-і-два-з-них-кусаються)). `-Werror` рятує вас від цього бага.

## 6. Зсув замість множення

Зсув ліворуч на n — це множення на 2ⁿ. Але біти, що виїхали за край, зникають.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    int x = 5;
    std::cout << (x << 3) << '\n';
    std::uint8_t b = 200;
    b = (std::uint8_t)(b << 1);
    std::cout << (int)b << '\n';
    int neg = -16;
    std::cout << (neg >> 2) << '\n';
}
```

**Вгадайте:** три числа.

**Зміни одне:** в останньому рядку замініть `(neg >> 2)` на `((std::uint8_t)neg >> 2)`.

**Що це означає:** зсув рухає біти; у знакового числа праворуч зверху заходять копії знакового біта ([теорія §3](lab-02-bits-dont-lie.md#3-шість-операторів-і-два-з-них-кусаються)).

## 7. Колір у трьох байтах

Колір `#FF8800` — це три байти: червоний, зелений, синій. Маленькі кольорові дисплеї в пристроях часто беруть лише 16 бітів на колір — формат RGB565.

```cpp
#include <cstdint>
#include <iostream>
int main() {
    std::uint32_t orange = 0xFF8800;
    int r = (orange >> 16) & 0xFF;
    int g = (orange >> 8) & 0xFF;
    int b = orange & 0xFF;
    std::cout << r << ' ' << g << ' ' << b << '\n';
}
```

**Вгадайте:** три числа.

**Зміни одне:** після рядка з друком додайте упаковку в RGB565: `std::uint16_t rgb565 = (std::uint16_t)(((r >> 3) << 11) | ((g >> 2) << 5) | (b >> 3));` і надрукуйте її через `std::hex`.

**Що це означає:** поле дістають зсувом до нуля й маскою, а пакують зсувом на місце й `|` ([теорія §4](lab-02-bits-dont-lie.md#4-маски-як-інструкція-розкладається-на-поля)). Де такі дисплеї — [у залізі](HARDWARE.md#lab-2--біти-не-брешуть).
