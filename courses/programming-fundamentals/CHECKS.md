# Самоперевірка — чи воно взагалі працює

Курс: [EN](README.md) · [Українською](README.uk.md) · Довідник машини: [ISA.uk.md](ISA.uk.md)

Найгірше, що може статись на цьому курсі, — писати два тижні й аж на захисті
дізнатись, що `PC` рухався не на стільки. Ці перевірки для того, щоб дізнаватись
за п'ять хвилин.

У теці [`checks/`](checks/) лежать готові набори команд. Запуск:

```bash
./build/ember < checks/lab-04.txt
```

Числа нижче **перевірені** на еталонній реалізації. Якщо у вас інші — щось не
збігається з [ISA.uk.md](ISA.uk.md), і краще шукати це зараз.

Формат виводу ваш: `ember` у всіх свій, і курс цього не регламентує. Збігатись
мають **значення**, а не пробіли.

## Lab 1 — `checks/lab-01.txt`

| Має бути | Чому |
|---|---|
| `get 0` показує `65`, `0x41`, `01000001`, `A` | чотири погляди на один байт |
| `get 2` показує `0`, `0x00`, `00000000` і крапку (не символ) | нуль не друкується |
| у дампі перший рядок закінчується `\|AB..............\|` | ASCII-колонка працює |
| `set 5000 1` дає повідомлення, а не падіння | межі перевіряються |
| `set 0 300` дає повідомлення | байт це 0…255 |

Якщо замість повідомлення програма впала зі звітом ASan — перевірка меж стоїть
**після** запису. Вона має стояти до.

## Lab 2 — `checks/lab-02.txt`

`reg a 200`, `reg b 100`, у пам'яті `ADD A, B` і `HALT`, потім три `step`.
`run` і `LOADI` з'являться лише в Lab 3, тому тут тільки `reg` і `step`.

| Має бути | Значення |
|---|---|
| `A` після першого `step` | `44` |
| `C` | `1` (виставлено) |
| `Z`, `N` | `0` |
| `PC` після першого `step` | `1` |
| `PC` після другого (`HALT`) | `2` |
| третій `step` | відмова з повідомленням, `PC` лишається `2` |

200 + 100 = 300 = 256 + 44. Якщо `A` дорівнює 300 або 255 — ви рахуєте не в
`uint8_t`. Якщо `C` нуль — перенесення береться не з дев'ятого біта. Якщо третій
`step` щось виконав — `HALT` не виставив ознаку зупинки.

## Lab 3 — `checks/lab-03.txt`

За `0x800` лежить `65 66 0`. Програма: `LOADH H, 0x0800`, `LOAD A, [H]`, `OUT`,
`INCH`, `LOAD A, [H]`, `OUT`, `HALT`.

| Має бути | |
|---|---|
| вивід | `AB` |
| `H` після `run` | `0x801` |
| `PC` | `9` |

Порожній вивід — `LOAD A, [H]` читає не звідти. Вивід `AA` — `INCH` не працює.
Один символ — `PC` після `LOADH` зсунувся не на 3.

Ще: `set16 0 0x1234`, потім `dump` — за адресою 0 має бути `34`, за 1 `12`.
Навпаки — це «старший уперед» (big-endian), а [ISA.uk.md §4](ISA.uk.md#4-кодування) вимагає «молодший уперед» (little-endian).

## Lab 4 — `checks/lab-04.txt`

Зворотний відлік з [ISA.uk.md §9](ISA.uk.md#9-дві-програми-щоб-перевірити-себе).

| Має бути | |
|---|---|
| вивід | `3 2 1` |
| кроків до `HALT` | `11` |
| `PC` в кінці | `8` |
| `A` | `0`, `Z` виставлено |

Найчастіші поломки:

- **нескінченний цикл** → `JZ`/`JNZ`, що спрацював, додає ще й розмір інструкції. Не має.
- **друкує `3 2 1 0`** → `DEC` виконується після `OUTN`, а перевірка `Z` дивиться на старе значення.
- **друкує лише `3`** → `JNZ` читає прапорець, який виставив не `DEC`, а щось інше.

## Lab 5 — `checks/lab-05.txt`

`CLS`, `LOADI A, 0x80`, `LOADH H, 0x0A00`, `STORE [H], A`, `SHOW`, `HALT` —
піксель **без** `PLOT`.

| Має бути | |
|---|---|
| `get 2560` (це `0xA00`) | `128` / `0x80` |
| на екрані | рівно один піксель, лівий верхній кут |

Піксель у правому кінці першого рядка → біти нумеруються не з того боку,
потрібно `7 - (x % 8)`. Піксель у другому рядку → крок рядка не 8. Порожній екран →
`SHOW` читає не з `0xA00`.

Далі: `plot(0,0)` має дати **той самий** байт `0x80` за тією самою адресою.
Якщо ні — ваш `plot` і ваш `show` рахують адресу по-різному.

## Lab 6

Перевіряти нічим — лаба про рефакторинг, і саме це є перевіркою:

| Має бути | |
|---|---|
| усі перевірки Lab 1–5 проходять **без змін** | `enum class Op` нічого не зламав |
| `sizeof(CPU)` | ваше число, у README, разом з поясненням вирівнювальних байтів |

Якщо після переходу на `enum class` щось із попередніх лаб перестало працювати —
отже, десь опкод порівнювався з числом, а не з `Op`. Це і є та помилка, яку
`enum class` мав спіймати.

## Lab 7 — `checks/lab-07.txt`

Лістинг `fact` з [ISA.uk.md §6](ISA.uk.md#розібраний-приклад), 30 байтів.

| Має бути | |
|---|---|
| вивід | `120` |
| кроків | `60` |
| `SP` після `run` | `0xFFF` |

**`SP` — головна перевірка.** Він має повернутись саме туди, звідки почав.
Якщо ні, десь `PUSH` без `POP` або `CALL` кладе не два байти.

Змініть першу пару байтів на `20 00` і `20 01` — обидва мають дати `1`.
Якщо `fact(0)` зациклився, перевірка `n == 0` не спрацювала.

Ще: `RET` без жодного `CALL` має дати **вашу** помилку про спустошення стека, а не
стрибок у нікуди.

## Lab 8

| Має бути | |
|---|---|
| `lex` на рядку `loop: JMP loop` | `Ident(loop) Colon Ident(JMP) Ident(loop) Newline Eof` |
| `lex` на `LOADI A, 0xGG` | помилка **з номером рядка**, не тихий нуль |
| `asm` на `HALT` | один байт `0x00` |
| `asm` на `JMP 0x0123` | три байти `30 23 01` |
| `fib.asm`, `fib(6)` | `8` |
| `fib.asm`, `fib(10)` | `55` |
| `SP` після `fib` | `0xFFF` |

Найнадійніша перевірка асемблера: зберіть `fact` **текстом** і порівняйте байти з
лістингом в [ISA.uk.md §6](ISA.uk.md#розібраний-приклад). Мають збігтись усі тридцять.
Якщо розходяться з якогось місця — там у вашій таблиці розмір інструкції на
одиницю інший.

Еталон для `fib`: 22 рядки вихідного коду, 35 байтів, мітка `fib` за `0x07`, `ret_a` за
`0x22`. `fib(6)` це 284 кроки, `fib(10)` — 2021. Різниця між цими двома числами і
є та лекція про те, чому наївна рекурсія дорога.
