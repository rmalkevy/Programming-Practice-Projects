Дві-три години один раз на початку семестру. Після цього ви більше ніколи не
відкладаєте лабу через «у мене не збирається».

Треба три речі: **компілятор** C++, **CMake** і **git**. Усі безкоштовні.

## 1. Поставити інструменти

### macOS

```bash
xcode-select --install
```

З'явиться вікно — погодьтесь, це кілька гігабайтів. Далі [Homebrew](https://brew.sh/),
якщо його ще немає, і:

```bash
brew install cmake
```

Компілятор (`clang`) і `git` уже прийшли з Xcode Command Line Tools.

### Ubuntu / Debian / Linux Mint

```bash
sudo apt update
sudo apt install build-essential cmake git clang
```

### Windows

Працюйте у **WSL** — це справжній Ubuntu усередині Windows. Без нього санітайзери
(головний інструмент курсу) на Windows або не запускаються, або поводяться інакше.

У PowerShell від імені адміністратора:

```powershell
wsl --install
```

Перезавантажтесь, відкрийте застосунок «Ubuntu», придумайте логін і пароль. Далі
ви **всередині Linux** — виконайте команди з розділу Ubuntu вище.

Далі весь курс живе у WSL: там і код, і збірка, і git. Файли видно з Windows за
шляхом `\\wsl$\Ubuntu\home\ваш_логін`, і VS Code відкриває їх напряму через
розширення WSL.

### Перевірка

```bash
c++ --version
cmake --version
git --version
```

Три відповіді з номерами версій — інструменти на місці. `command not found`
означає, що крок вище не доробився.

## 2. Перший запуск

```bash
mkdir -p ~/pf && cd ~/pf
printf '#include <iostream>\nint main() { std::cout << "ok\\n"; }\n' > scratch.cpp
c++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined scratch.cpp -o scratch
./scratch
```

**Очікуй:** `ok`.

Цей рядок `c++ …` ви виконаєте за семестр разів сто. Він є на початку кожного
файлу notes. Що означають прапорці:

| Прапорець | Навіщо |
|---|---|
| `-std=c++17` | версія мови |
| `-Wall -Wextra` | «попереджай про підозріле» |
| `-Werror` | «і вважай попередження помилкою» |
| `-fsanitize=address,undefined` | вшити в програму перевірки пам'яті |
| `-o scratch` | як назвати готову програму |

Якщо щось пішло не так — [errors.notes.md](errors.notes.md).

## 3. Термінал за десять хвилин

Термінал — це той самий комп'ютер, тільки командами замість кліків. Ви завжди
**десь стоїте** (поточна тека), і команди діють звідти.

| Команда | Що робить |
|---|---|
| `pwd` | де я зараз |
| `ls` | що тут лежить |
| `ls -la` | те саме, докладно й разом із прихованими файлами |
| `cd ember` | зайти в теку `ember` |
| `cd ..` | на рівень вище |
| `cd ~` | у домашню теку |
| `mkdir ember` | створити теку |
| `cat file.txt` | вивалити файл на екран |
| `less file.txt` | гортати файл (`q` — вийти) |
| `rm file.txt` | видалити файл (**без кошика**, назавжди) |

Про шляхи: `.` — тека, де я стою; `..` — та, що вище; `~` — домашня. Шлях, що
починається з `/`, відраховується від кореня диска, будь-який інший — від того
місця, де ви стоїте. Саме тому `./build/ember` працює тільки з кореня проєкту.

Чотири клавіші, які економлять години:

- **Tab** — дописує назву файлу. Натискайте постійно; це ще й перевірка, що файл справді так називається.
- **Стрілка вгору** — попередня команда. Збирати й запускати — це дві команди, які ви ганяєте по колу.
- **Ctrl-C** — зупинити програму, що зациклилась.
- **Ctrl-D** — «ввід скінчився». Так коректно виходять з prompt `ember`, якщо забули `quit`.

Зберегти вивід у файл (стане в пригоді для README):

```bash
./build/ember < commands.txt > output.txt 2>&1
```

`>` — звичайний вивід у файл, `2>&1` — туди ж і повідомлення про помилки
(санітайзер пише саме туди).

## 4. Git за п'ятнадцять хвилин

Курс вимагає **один публічний репозиторій з першого дня** і **тег після кожної
лаби**. Ось рівно стільки git, скільки для цього треба.

### Один раз на машині

```bash
git config --global user.name "Ваше Ім'я"
git config --global user.email "ваш@email"
```

Це підпис під кожним комітом. Без нього git відмовиться зберігати.

### Створити репозиторій

```bash
cd ~/pf/ember
git init
git branch -M main
```

### Щоденний цикл

```bash
git status                     # що змінилось
git add .                      # взяти всі зміни
git commit -m "lab-01: dump and get"   # зберегти їх з підписом
git log --oneline              # історія
```

Коміт — це **знімок** проєкту. Робіть його щоразу, коли щось запрацювало, а не
раз на два тижні. Повідомлення пишіть по ділу: `lab-02: ALU sets carry` краще за
`fix`.

### Що не потрапляє в репозиторій

Файл `.gitignore` у корені (у [скелеті](starter/README.md) він уже є):

```txt
build/
*.o
scratch
scratch.cpp
```

Тека `build/` — це результат збірки. Вона відтворюється однією командою й важить
багато; у git їй не місце. Якщо `git status` показує сотні файлів із `build/` —
`.gitignore` не працює, перевірте, що він у корені й називається саме так.

### Тег після кожної лаби

```bash
git tag lab-01
git push origin lab-01
```

Тег — закладка на конкретному коміті: «ось тут лаба 1 була здана». Викладач
дивиться саме на них.

### Викласти на GitHub

Створіть порожній репозиторій на github.com (**без** README, щоб не було
конфлікту), і:

```bash
git remote add origin https://github.com/ВАШ_ЛОГІН/ember.git
git push -u origin main
```

Далі просто `git push` після кожної порції комітів. GitHub попросить не пароль, а
**personal access token** — зробіть його в Settings → Developer settings →
Personal access tokens.

### Якщо щось пішло не так

| Ситуація | Що зробити |
|---|---|
| `git status` червоний, а я нічого не зберіг | `git add .` і `git commit -m "..."` |
| Зіпсував файл, коміту ще не було | `git checkout -- шлях/до/файлу` — повернути як було |
| Закомітив `build/` | додайте в `.gitignore`, потім `git rm -r --cached build` і закомітьте |
| `push` відхиляє: `rejected` | `git pull --rebase` і знову `push` |
| Все заплуталось | нічого не видаляйте. Покажіть викладачу `git log --oneline` і `git status` — з цього стану завжди є вихід |

**Ніколи не видаляйте теку `.git`, щоб «почати заново».** Разом з нею зникає вся
історія — а вона і є доказ того, що ви працювали всі шістнадцять тижнів.

Копіюйте з термінала **як є**, у трьох зворотних лапках:
